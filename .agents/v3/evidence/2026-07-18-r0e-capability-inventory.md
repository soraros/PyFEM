## Proposed public and portfolio decisions

1. **Root API:** change `pyfem.run` into an adapter over normalized specs, compilation, a typed analysis request, and a provenance-bearing solution. Retire the exact `PyFEMAPI` stateful camel-case class and the public `NodeSet`/`ElementSet` root exports; the replacements are authored builders/specs, not compatibility carriers.
2. **CLI and legacy files:** preserve the `pyfem` command name only as a proposed convenience; change its implementation to explicit adapters and typed requests. Keep `.pro`/`.dat` support as a bounded adapter portfolio, with accepted syntax declared and checked independently. Retire pickle input/checkpoint compatibility rather than deserialize legacy runtime graphs.
3. **GUI:** propose retirement of the current `pyfem-gui`/PySide6 entry point. No GUI successor is proposed until an explicit optional-dependency and workflow decision is approved. This public retirement remains open for I0/delegator approval.
4. **RVE/FE2:** change while preserving the physical intent. Compile RVE boundary selection and periodic/prescribed programs explicitly; localize homogenized stress/tangent as results; retain `MicroModel` only as an explicit slower nested-material backend with committed/trial/restart and cost semantics. Do not silently drop it.
5. **ROM:** change while preserving snapshot collection, POD basis construction, and reduced solve as explicit result/analysis capabilities. Retire the exact legacy HDF5 schema as a contract and retire the unimplemented linear/quadratic manifold placeholders unless a later decision supplies semantics and a correctness matrix.
6. **Current v3 prototype:** preserve reusable numerical kernels and accepted foundation primitives, but retire the flat `ProblemDefinition`/`LoadedProblem` whole-problem carrier, string registry, prototype assembly bridge, and direct `solve_*` API as architecture or public compatibility constraints.
